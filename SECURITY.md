# Политика безопасности

## Поддерживаемые версии

Marchi — проект в статусе `0.x` (см. [раздел «Политика 0.x» в USER_GUIDE.md](docs/USER_GUIDE.md#политика-0x-и-совместимость)):
API и формат данных могут меняться между минорными версиями. Исправления безопасности
выпускаются только для последней опубликованной версии — предыдущие версии не
поддерживаются задним числом.

## Как сообщить об уязвимости

**Не создавайте публичный Issue.** Используйте приватный канал GitHub Security
Advisories:

<https://github.com/yurydemin/marchi/security/advisories/new>

В сообщении укажите, по возможности:

- версию Marchi (вывод `marchi --version` или тег образа `ghcr.io/yurydemin/marchi`);
- шаги для воспроизведения;
- потенциальное влияние (какие данные/функции затронуты).

Ответ на первичное сообщение — в течение 7 дней. Если уязвимость подтверждается,
согласуем срок и формат раскрытия перед публикацией.

## Что считается уязвимостью безопасности

В частности: обход разблокировки/CSRF/rate-limiting, утечка секретов (IMAP-пароли,
OAuth2-токены, S3-ключи, Master Key) в открытом виде — из логов, БД, файловой системы
или по сети, path traversal в эндпоинтах скачивания, XSS в просмотрщике писем, SQL-инъекции.

Не считается уязвимостью в этом контексте: работа с уже расшифрованными данными
локальным пользователем, у которого и так есть доступ к Master Key/данным на диске —
модель угроз Marchi (self-hosted, один Master Key на инсталляцию) не предполагает
защиты от того, кто уже прошёл разблокировку.

## Зависимости

`govulncheck` запускается в CI на каждый push/PR ([`.github/workflows/ci.yml`](.github/workflows/ci.yml)).
Dependabot следит за обновлениями Go-модулей и GitHub Actions
([`.github/dependabot.yml`](.github/dependabot.yml)).
